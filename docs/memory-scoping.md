# 记忆范围与更新

## 存储与隔离

- Spring 运行时只创建一个 `MemoryStore`，供 `memory` 工具、上下文组装和摘要记忆提炼共享。
- 结构化记忆写入串行化，先原子替换文件再提交内存状态；读取结果是独立副本。
- `project` 为新记忆的默认范围，绑定当前会话的规范化工作目录；`agent` 还绑定智能体定义的 code。
- `user` 用于用户明确要求跨工作区保存的偏好或事实。仅显式用户记忆且标记 `preference` 的条目可不经任务相关性过滤常驻。
- 工作目录来自执行上下文；后台任务使用捕获的来源范围，或通过现有 `WorkspaceRegistry` 查询来源会话。模型不能传入路径来切换记忆范围。
- 此范围是记忆召回及工具操作边界，不是操作系统文件权限或多用户安全隔离。

## 召回与纠错

- 项目事实和操作经验先经过范围与文本相关性准入，再排序，不补入无关记录凑数量。
- 中文使用字符二元组的保守文本重合检查，英文使用词匹配；它不是语义理解，可能漏召回。操作经验仍保留现有任务类型门槛。
- 访问次数只作诊断，不因反复注入提高记忆排名；经验只统计真正进入提示词的条目。
- “错了”“不对”等普通对话不会自动降低任何经验的置信度。明确指定经验 ID 的反馈仍可使用原有接口。
- 更新长期记忆时，先 `memory(action="search"/"list")` 找到 ID，再 `memory(action="update", id="...", content="...")`。不创建第二条相冲突的记忆；保留原 ID、范围和修改前版本。旧版本不进入模型上下文。
- 查询、更新和删除都遵守同一范围限制；不存在或不属于当前范围的 ID 返回错误。

## 旧数据兼容

- 原 `memory/MEMORIES.json` 不删除、不批量重写。读取无范围记录时，默认归入原配置工作目录；带 `agent` 标签的旧记录归入该目录的默认智能体。
- 旧 `user_explicit` 记录只有明确带 `user` 标签且不带 `project/agent` 标签，才保留全局范围。
- 无范围的旧操作经验只在默认工作区可用；新接受的经验记录来源范围。
- 旧 `MEMORY.md` 仅在默认工作区按相关段落召回。
- 旧每日笔记可能混合多个工作区，保留文件但停止自动注入。新笔记保存至 `memory/workspaces/<工作目录 SHA-256>/notes/YYYYMM/YYYYMMDD.md`，按来源工作区读取。

不更改上下文压缩比例、工具循环、全局技能或模型配置，也不增加前台模型调用。
